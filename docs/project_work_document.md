# HARC-RAG Project Work Document

## Project Overview

HARC-RAG is a Hallucination-Aware Retrieval-Augmented Generation system. It lets a user upload PDF documents, indexes the document content, retrieves relevant chunks for a question, asks a local LLM through Ollama, calculates confidence scores, and shows the answer with source chunks in a browser UI.

The project has three main parts:

- `frontend/`: browser interface for uploading PDFs and asking questions.
- `src/harc_rag/`: Python backend and RAG pipeline.
- `tests/`: unit tests for the backend modules.

## Runtime Flow

1. User opens `http://127.0.0.1:8080/app/`.
2. User uploads a PDF.
3. FastAPI saves the PDF in `data/uploads/`.
4. `DocumentLoader` extracts text from the PDF.
5. `TextSplitter` chunks the document.
6. `MiniLMEmbeddingModel` creates vector embeddings.
7. Chunks are stored in FAISS for dense search and BM25 for keyword search.
8. User asks a question.
9. Hybrid retrieval combines dense and BM25 results with Reciprocal Rank Fusion.
10. `PromptBuilder` creates a context-grounded prompt.
11. Ollama generates the answer.
12. If the document does not contain enough information, the pipeline now falls back to a general LLM prompt.
13. The uncertainty system calculates retrieval, generation, evidence, and joint confidence.
14. The router decides whether verification is needed.
15. API returns answer, confidence values, verification reason, retrieved chunks, and source text to the frontend.

Defines the Python project metadata, dependencies, development tools, and build backend. Important dependencies include FastAPI, Uvicorn, FAISS, sentence-transformers, Ollama, pypdf, numpy, and rank-bm25.

## Frontend Files

### `frontend/index.html`

Main HTML page for the web app. It defines:

- Sidebar with project title.
- Backend status indicator.
- PDF upload control.
- Document list.
- Chat area.
- Question input form.

It loads `styles.css` for styling and `app.js` for behavior.

### `frontend/styles.css`

Styles the full web interface. It controls the sidebar, chat layout, upload controls, message bubbles, source cards, confidence metric cards, and backend status colors.

### `frontend/app.js`

Controls all browser-side behavior:

- Checks backend health with `GET /health`.
- Uploads PDF files to `POST /documents/upload`.
- Sends user questions to `POST /chat`.
- Renders user and assistant messages.
- Displays confidence, retrieval, generation, evidence, verification, retrieved chunks, and source snippets.
- Shows friendly error messages if the backend is unavailable.

## Backend API Files

### `src/harc_rag/api/main.py`

Creates the FastAPI app. On startup it initializes:

- MiniLM embedding model.
- FAISS vector store.
- BM25 retriever.
- Dense retriever.
- Hybrid retriever.
- Document indexing service.
- HARC-RAG pipeline.

It also enables CORS and mounts the frontend at `/app`.

### `src/harc_rag/api/routes.py`

Defines backend HTTP endpoints:

- `GET /health`: returns backend status.
- `POST /chat`: receives a question and returns a RAG answer with metadata.
- `POST /documents/upload`: saves and indexes uploaded PDF files.

It stores global references to the active pipeline and indexer.

### `src/harc_rag/api/models.py`

Defines Pydantic request and response models:

- `ChatRequest`: user question.
- `SourceChunk`: source text and score.
- `ChatResponse`: answer, confidence values, verification data, retrieved chunk count, and sources.

### `src/harc_rag/api/indexing.py`

Defines `DocumentIndexingService`. It performs the full indexing path:

1. Load PDF.
2. Split document into chunks.
3. Embed chunks.
4. Add embeddings to FAISS.
5. Add chunks to BM25.

## Document Loading

### `src/harc_rag/document/loader.py`

Loads PDFs using `pypdf`. It extracts text from every page and returns a `Document` object. It rejects unsupported file types and empty PDFs.

### `src/harc_rag/document/models.py`

Defines the `Document` dataclass with file name, path, text, page count, and metadata.

### `src/harc_rag/document/exceptions.py`

Defines custom document loading errors:

- `DocumentLoaderError`
- `UnsupportedFileTypeError`
- `EmptyDocumentError`

## Chunking

### `src/harc_rag/chunking/models.py`

Defines the `Chunk` dataclass. A chunk contains chunk id, text, start/end positions, and metadata.

### `src/harc_rag/chunking/strategies.py`

Defines the abstract `ChunkingStrategy` interface.

### `src/harc_rag/chunking/character_strategy.py`

Splits a document by character count. Default size is 500 characters with 50 characters of overlap.

### `src/harc_rag/chunking/word_strategy.py`

Splits text while trying not to cut words in the middle. It extends the character strategy but adjusts chunk boundaries to spaces.

### `src/harc_rag/chunking/splitter.py`

Wrapper class that receives a chunking strategy and applies it to a document.

### `src/harc_rag/chunking/exceptions.py`

Defines errors for invalid chunking configuration.

### `src/harc_rag/chunking/__init__.py`

Package marker for the chunking module.

## Embedding

### `src/harc_rag/embedding/interfaces.py`

Defines the abstract `EmbeddingModel` interface.

### `src/harc_rag/embedding/minilm.py`

Uses `sentence-transformers/all-MiniLM-L6-v2` to create embeddings for chunks and user queries.

### `src/harc_rag/embedding/models.py`

Defines the `Embedding` dataclass with chunk id, vector, and metadata.

### `src/harc_rag/embedding/service.py`

## Vector Store

### `src/harc_rag/vectorstore/interfaces.py`

Defines the abstract `VectorStore` interface.

### `src/harc_rag/vectorstore/models.py`

### `src/harc_rag/vectorstore/exceptions.py`

## Retrieval

### `src/harc_rag/retrieval/models.py`

Defines `RetrievalResult`, which contains a retrieved chunk and a score.

### `src/harc_rag/retrieval/interfaces.py`

Defines the abstract `Retriever` interface.

### `src/harc_rag/retrieval/bm25_retriever.py`

Implements keyword retrieval using BM25. It tokenizes chunks with `.split()`, ranks chunks by BM25 score, and returns the top results.

### `src/harc_rag/retrieval/dense_retriever.py`

Uses the embedding model and FAISS vector store to retrieve semantically similar chunks.

### `src/harc_rag/retrieval/fusion.py`

Implements Reciprocal Rank Fusion. It combines dense and BM25 rankings into one ranked list.

### `src/harc_rag/retrieval/hybrid_retriever.py`

Runs both dense retrieval and BM25 retrieval, then fuses the results.

### `src/harc_rag/retrieval/config.py`

Defines retrieval configuration such as `top_k` and optional score threshold.

### `src/harc_rag/retrieval/conversation_retriever.py`

Builds a retrieval query using conversation history plus the current user question.

### `src/harc_rag/retrieval/service.py`

Service wrapper for normal retrieval and retrieval with memory.

### `src/harc_rag/retrieval/exceptions.py`

Defines retrieval-related errors.

## Generation

### `src/harc_rag/generation/interfaces.py`

Defines the abstract `LLM` interface.

### `src/harc_rag/generation/ollama.py`

Implements LLM generation through the Ollama Python client using `client.generate()`.

### `src/harc_rag/generation/prompt_builder.py`

Builds prompts for the LLM.

It has two prompt styles:

- Document-grounded RAG prompt: tells the LLM to answer only from retrieved context.
- General fallback prompt: used when the document-grounded answer says the uploaded documents do not contain enough information.

### `src/harc_rag/generation/generator.py`

Thin wrapper that calls the generation service.

### `src/harc_rag/generation/service.py`

Thin wrapper around an `LLM` implementation.

### `src/harc_rag/generation/models.py`

Defines dataclasses for generation request and response.

### `src/harc_rag/generation/exceptions.py`

Defines generation errors.

## Pipeline

### `src/harc_rag/pipeline/pipeline.py`

Main orchestration file for answering questions. It:

- Retrieves relevant chunks.
- Builds the RAG prompt.
- Generates an answer.
- Falls back to general LLM knowledge if the document answer is insufficient.
- Estimates confidence.
- Routes low-confidence answers to verification when appropriate.
- Returns answer metadata and sources.

### `src/harc_rag/pipeline/service.py`

Simple service wrapper around `HARCRAGPipeline`.

## Uncertainty and Confidence

### `src/harc_rag/uncertainty/models.py`

Defines `ConfidenceScore` and `JointUncertainty`.

### `src/harc_rag/uncertainty/retrieval_confidence.py`

Calculates retrieval confidence from retrieved scores. It normalizes RRF scores so a good fused retrieval result does not look like low confidence just because RRF scores are small.

### `src/harc_rag/uncertainty/generation_confidence.py`

Estimates answer confidence by checking for uncertain phrases such as "maybe", "not sure", and "insufficient information".

### `src/harc_rag/uncertainty/evidence_confidence.py`

Calculates how similar the generated answer is to the retrieved context.

### `src/harc_rag/uncertainty/semantic_similarity.py`

Uses sentence-transformer cosine similarity when available. If that fails, it falls back to simple lexical word overlap.

### `src/harc_rag/uncertainty/weighting.py`

Chooses dynamic weights for retrieval, generation, and evidence confidence based on retrieval strength.

### `src/harc_rag/uncertainty/estimator.py`

Combines retrieval, generation, and evidence confidence into one joint confidence score.

### `src/harc_rag/uncertainty/threshold.py`

Calculates an adaptive threshold. Longer questions get a lower threshold than short questions.

### `src/harc_rag/uncertainty/service.py`

Service wrapper for the joint estimator.

### `src/harc_rag/uncertainty/interfaces.py`

Defines the abstract uncertainty estimator interface.

### `src/harc_rag/uncertainty/exceptions.py`

Defines uncertainty-related errors.

## Routing

### `src/harc_rag/routing/models.py`

Defines `RoutingDecision`, including whether verification should run and why.

### `src/harc_rag/routing/cost.py`

Estimates verification cost from answer length and context length.

### `src/harc_rag/routing/router.py`

Decides whether to verify an answer. Low confidence plus affordable verification triggers verification. Very large context skips verification.

### `src/harc_rag/routing/service.py`

Service wrapper around the adaptive router.

### `src/harc_rag/verification/models.py`

## Generated and Cache Files

Files inside `__pycache__/`, `.pytest_cache/`, `.uv-cache/`, and `.venv/` are generated environment/cache files. They are not part of the handwritten application logic.

## Important Notes

- The backend expects Ollama to be running locally.
- The default model is `qwen2.5:3b`, configurable with `HARC_RAG_MODEL`.
- The default Ollama host is `http://127.0.0.1:11434`, configurable with `HARC_RAG_OLLAMA_HOST`.
- The frontend expects FastAPI at `http://127.0.0.1:8080`.
- The uploaded-document answer is tried first. General LLM fallback is used only when the document-grounded answer says the documents do not contain enough information.
